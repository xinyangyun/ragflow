第一章 文档处理

第一节 解析与清洗

文档解析会将书籍转换成有序文本段落。纯文本按非空行读取，Word 按段落读取，文本型 PDF 按页提取文字。
目录中的章节名会重复出现在正文中。清理目录可以减少重复标题对向量检索的干扰。

第二节 章节切分

章节识别会匹配“第一章”“第一节”等编号。层级合并会为正文补齐祖先标题，让检索结果保留所属章节。
没有识别到章节结构时，程序才按分隔符和 chunk_size 合并段落；有章节结构时不使用 chunk_size 强制切分。

第二章 向量检索

第一节 向量模型

千问 text-embedding-v2 将文本转换为数值向量。文档和查询必须使用相同的模型，保证向量具有可比较的语义空间。
API Key 应通过环境变量提供，不应写进代码、测试书籍或 Git 仓库。

第二节 召回优化

检索通过比较查询向量和文档向量的余弦距离返回候选内容。距离越小，语义越接近。
提高检索准确率可以从文档清洗、章节切分、Top-K 和重排序入手。增加 Top-K 会扩大召回范围，但也可能引入无关文本。

第三章 数据管理

第一节 Chroma 持久化

书籍分块、向量和元数据保存在脚本同级的 book_chroma_db 目录，默认 collection 名称是 book-demo。
可以通过 --chroma-path 指定其他目录。同一源文件重复写入时会替换旧分块，其他源文件的数据不会被删除。

第二节 离线测试

使用 --chunks-only 参数只进行解析和切分，不调用千问接口，不写入 Chroma。
扫描版 PDF 不含可直接提取的文字，应先进行 OCR。这个独立 demo 不包含 DeepDOC 的 OCR 和版面识别流程。
