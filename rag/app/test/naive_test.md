# 企业知识库检索测试

## 文档切分

RAG 系统通常会先读取原始文档，再按照段落、换行和句末标点切分文本。
合理的分块大小能够保留完整语义，也能避免单个文本块包含过多无关内容。
如果分块过小，问题和答案可能被拆散；如果分块过大，检索结果就容易混入无关内容。

## 向量生成

文档切分完成后，系统会使用向量模型将每个文本块转换为数值向量。
用户提问时，查询文本也会使用同一个模型生成向量，随后通过余弦相似度比较查询和文档的语义距离。
文档向量和查询向量必须来自同一个模型，否则它们可能不在同一个可比较的向量空间中。

## 检索效果

Top-K 参数决定一次召回多少个候选文本块。较大的 Top-K 可以扩大召回范围，但也可能带来更多无关内容。
重排序模型会对初步召回的结果再次评分，将最相关的文本排在前面，从而帮助生成模型获得更准确的上下文。
实际项目中还应清理重复内容、保留标题信息，并根据文档长度调整 chunk_size 和重叠比例。

## Chroma 存储

独立 demo 可以把文本块、向量和来源信息保存到本地 Chroma 数据库。
重复运行同一个文档时，程序会根据稳定 ID 更新对应的文本块；数据库目录可以通过命令行参数指定。
